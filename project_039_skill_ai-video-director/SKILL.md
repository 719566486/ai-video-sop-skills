# AI Video Director

Deliver a playable movie, not just a screenplay, storyboard, provider links or disconnected clips. This is an agent-operated skill: Python handles deterministic checks and editing; Codex uses its native image tool and the connected Kling tools. Read [the production contract](references/production-contract.md) when creating the plan and [the provider contract](references/providers.md) before external generation. No other skill is required.

## Input and autonomy

Accept a complete script or one/two sentences plus duration; images are optional. Preserve explicit story, identity, voice, music, framing and workspace instructions. Defaults: 60 seconds if missing, 16:9, 1080p, 24 fps, the user's language. Infer a coherent creative direction; disclose assumptions in a short message and proceed. Do not run a long interview, require a pitch round, or stop for storyboard approval unless the user requested it. If identity/rights or essential plot meaning cannot be inferred, ask one consolidated question while doing independent work.

Use the user's workspace, otherwise a fresh project under the current workspace. Never hardcode an author's machine path. A capability/permission problem is a specific blocker, not permission to switch providers or quietly deliver a slideshow. A connected paid generation request can authorize its necessary operations; inspect existing scope before asking. Respect runtime approvals and provider retry requirements. Missing payment/upload authorization, unknown account region or an exact budget that cannot be bounded may require one targeted question. Do not treat skill invocation as unlimited spending.

## Execute

1. **Preflight and resume.** Locate built-in image generation, Kling `who_am_i`, membership, upload, generation and query tools; Python 3.10+ and FFmpeg/ffprobe. Run `scripts/video_pipeline.py doctor`. Resolve model arguments from live capabilities, not a hardcoded model list. Resume `production.json` and `jobs.json` before doing new work. Read existing receipts after interruptions; never restart an entire batch by default.
2. **Write the complete production bible.** Save `BRIEF.md` and `SCRIPT.md`: purpose/audience, genre/style/light/palette, beat outline, full story, timings, exact dialogue/narration and performance/tone, music/FX plan, transitions, delivery requirements. Create `production.json` via `init`, then fill it using the production contract. Define stable C/S/P IDs for characters, settings and props, role-tagged references, immutable features and changeable features. Plan multi-angle character/scene/prop reference assets; omit an irrelevant asset class explicitly, do not invent a character just to fill a form. Allocate integer frames exactly to the requested duration.
3. **Make the visual bible with native imagegen.** Establish a canonical character face/body/costume; generate useful front/three-quarter/profile/back views, scene geography/reverse views, prop structure/detail views. Keep missing angles plausible and mark them inferred. Inspect generated assets; don't propagate a bad hand, costume or device. Reference sheets are for identity checking, not a literal multi-panel video frame. Copy selected native outputs into the project; record provenance. Never silently use a paid image API because native images were saved elsewhere.
4. **Make each shot's frame.** Generate a clean single-scene start frame using the locked references. Add an end frame only if it clarifies a feasible change with the same geography and objects. Write separate image, camera and action prompts, including start/action/end, handedness, contact, screen direction, gaze, occlusions, lens/framing and subject vs camera motion. Use one dominant physical action per shot. No generated text for exact captions or UI; add exact text in post. Validate with `validate` before generation.
5. **Generate motion deliberately.** Read the provider contract. Upload only required references, persist returned URLs privately and use `inputType: URL` where declared. Reserve each job locally before the paid call; save its receipt and ID immediately, then record it. Poll known IDs with bounded backoff. Download completed sources promptly. A task marked successful is not a visually accepted shot. Neither a timeout nor a receipt-writing error authorizes a duplicate charge.
6. **Review the actual motion.** Inspect start/middle/end and risky continuous intervals: face/costume, hands/tool contact, object permanence, geometry, actual action, axis and unwanted text. For fine handwork or an object passing between hands, inspect the whole selected interval densely. Record the source hash, reviewed source range and what was inspected in `review`. Trim a clearly good interval if the action remains legible; disclose retiming and do not substitute digital zoom for missing action. Keep discarded sources. Follow provider instructions before any paid retry; a change of creative intent needs user direction. If unresolved, report the precise incomplete shot instead of labelling the film complete.
7. **Build sound and edit.** Generate exact narration/dialogue with an authorized TTS or audio tool; keep speaker voice stable. Check pronunciation and timing against actual audio. Use authorized music, separate speech/music/FX tracks and duck music under speech. Native Kling audio can contain unwanted music/voices: inspect before keeping it. Use local assembly for ordinary cuts, overlays, subtitles and mixing; use another rendering framework only when needed/selected, reading that framework's instructions then. The included assembler supports deterministic cuts, retiming, native audio, subtitle burn-in and separate audio tracks. Author special transitions separately and revalidate their frame accounting.
8. **Verify exported media and deliver.** Run `assemble`, then `qa` on the real MP4. Inspect its actual opening frame, major beats, adjacent cut frames, captions and final frame; listen to dialogue and mix when playback is available. Check decode, dimensions, duration, frame count, audio presence/loudness and asset provenance. Technical checks cannot certify visual correctness or listening. Report unfinished checks explicitly. Deliver the final MP4, cover, SRT if applicable, script, manifest, expense summary and brief QA/limitations. Say native resolution versus upscaled delivery accurately. Stop only at the agreed deliverable or a real blocker.

## Deterministic helpers

Run `python <this-skill>/scripts/video_pipeline.py --help`. `init` creates a scaffold; it does not author creative content or generate media. `reserve`/`record` maintain a private job ledger; they do not call Kling. `assemble` requires accepted, hash-bound source ranges and will not overwrite an existing final. `qa` reports technical facts only. Read [the production contract](references/production-contract.md) for commands and fields.

## Practical choices distilled from production

- Film history/explainers: map each spoken sentence to evidence or a concrete scene; don't distribute footage evenly by chapter or endlessly loop clips.
- Cultural/nonfiction films: separate sourced facts, reconstruction and fiction; verify claims before scripting. A reference face or photo is not proof of an event or craft accuracy.
- Product films: preserve real shape, controls, labels and working logic. Use composited verified UI instead of plausible invented interfaces.
- Wedding/character films: distinguish each costume, front/back ornaments, helpers and protagonists; verify whole arm anatomy, transfers, entry/exit and cut boundaries.
- Craft close-ups: stable tools with motionless hands still fail an action shot. Identical first/end frames can suppress movement; only select this constraint when stillness is intended.
- Revisions: change only the requested attribute, invalidate affected downstream assets by hash, preserve prior masters, and use the latest explicit user instruction over an older brief.
